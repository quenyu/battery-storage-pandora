# Устройство приложения

```text
Swagger / HTTP-клиент → Go → PostgreSQL
```

Используются pgx и явный SQL. Без ORM, отдельных сервисов и дополнительных брокеров.

Основные файлы:

- `cmd/pandora/main.go` — запуск сервера и миграций.
- `internal/api/routes.go` — маршруты `/api`.
- `internal/api/server.go` — HTTP, чтение и служебные ответы.
- `internal/api/commands.go` — общая транзакция и повтор запросов.
- `internal/api/catalog.go` — сотрудники и карты.
- `internal/api/batteries.go` — действия с АКБ.
- `internal/api/query.go`, `reads.go` — SQL чтения и списки.
- `internal/api/input.go`, `errors.go` — проверка запросов и единые ошибки.
- `migrations` — последовательные миграции БД.
- `swagger` — локальные файлы Swagger UI.

Порядок изменяющей команды: проверить JSON и ключ → начать транзакцию → зарезервировать ключ → определить сотрудника по карте → заблокировать АКБ → записать состояние и операцию → сохранить ответ → COMMIT.

FOR UPDATE исключает одновременную выдачу одной АКБ. UNIQUE текущего адреса разрешает гонку двух АКБ за одно место. При конфликте изменения откатываются; при повторе возвращается сохранённый ответ. История защищена от изменения в БД.

HTTP-клиент не задаёт источник движения, держателя или текущее состояние напрямую. Сотрудник определяется по карте, источник берётся из заблокированной строки АКБ. Авторизации API нет.

Применённые миграции не изменяются. Старые данные сохраняются в `legacy_*`; переход проверяется в отдельной тестовой БД.
