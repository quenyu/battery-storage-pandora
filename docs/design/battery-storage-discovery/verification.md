# Проверки

Проверки выполняются в отдельных схемах БД `pandora_test` с обычной ролью приложения. Рабочие данные не очищаются.

Интеграционные сценарии:

- STORE → TAKE → RETURN → MOVE; совпадение состояния, адресов и истории.
- Два TAKE одной АКБ: один успех, один конфликт.
- Две АКБ на один адрес: один успех, один конфликт.
- Чужой RETURN запрещён; держатель сохраняется.
- Смена карты сохраняет историю и позволяет тому же сотруднику вернуть АКБ.
- Повтор после потерянного ответа не создаёт новую операцию.
- Повтор сохранённого конфликта возвращает первоначальный конфликт.
- Сбой после записи состояния/операции полностью откатывает изменения.
- Одинаковые параллельные ключи создают один результат.
- Некорректный адрес, JSON, UUID, фильтры и курсоры отклоняются.
- Поиск по строковому коду сохраняет ведущие нули и точное написание.
- Перенос адресов и истории сохраняет ID, время и все исходные строки; несовместимая история отклоняет миграцию.

Все 19 маршрутов проверяются против OpenAPI. Примеры запроса и ответа валидируются. Swagger проверяется через реальные Try it out: создание сотрудника, повтор, чтение, назначение карты и STORE. Заголовок и форма не содержат авторизации и версионирования API.

Команды: `go test ./... -count=1`, `go vet ./...`, `go build ./cmd/pandora`. Переменные тестовой БД и запуск описаны в корневом README.
