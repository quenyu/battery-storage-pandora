# Модель данных

Четыре предметные таблицы и одна таблица повторов запросов:

| Таблица | Данные |
|---|---|
| employees | Сотрудник: имя, необязательный табельный номер, активность |
| employee_credentials | Карты сотрудника и их активность; значения сохраняются строками |
| batteries | Код АКБ, статус, текущий адрес или держатель, номер состояния |
| battery_operations | Неизменяемая история: тип, АКБ, сотрудник, карта, исходный и конечный адрес/держатель, время |
| idempotency_requests | Ключ, hash запроса и первоначальный HTTP-ответ |

Сотрудник имеет несколько карт; смена карты не меняет employee_id. Каждая АКБ имеет одну текущую строку и последовательность операций. Исторические ссылки не удаляются.

Адреса source_location и destination_location хранятся текстом в операции. current_location в АКБ — текущее место. Формат: положительные числа шкаф.полка.ячейка без ведущих нулей. UNIQUE current_location запрещает две АКБ на адресе.

STORED требует адрес и отсутствие держателя. ISSUED требует держателя и отсутствие адреса. Каждой версии соответствует ровно одна операция; конец последней операции совпадает с текущей строкой.

Шкафы, полки и ячейки отдельными таблицами не ведутся. Старые таблицы мест находятся только в архиве перенесённых данных. Техническая колонка scope сохранена для совместимости схемы; все новые запросы используют одно значение `pandora`.

Полный DDL — `schema.sql`; для существующей БД используются миграции.
