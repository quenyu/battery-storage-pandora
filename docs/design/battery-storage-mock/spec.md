# Спецификация демонстрационного макета

29.09.2026. Статус: проектный пакет для макета; backend по этому контракту в текущем запросе не реализуется. Подтверждены: одна АКБ в ячейке, четыре операции, сотрудник получает для себя и возвращает сам.

## Цель и объём

Показать корректную PostgreSQL-модель и REST API учёта АКБ через Swagger. Ценность демонстрации: воспроизводимый цикл STORE → TAKE → RETURN → MOVE с полной историей, безопасными повторами и защитой от конкурентной выдачи.

Объём: ручные сотрудники/credential, шкафы/полки/ячейки, экземпляры АКБ, четыре команды, текущее состояние, история по АКБ/автору/месту, содержимое ячейки, АКБ у сотрудника, замена/отзыв credential, отключение пустой ячейки, учёт необязательной метки устройства.

За пределами задачи: вход и роли, пользовательский frontend, оборудование, внешние справочники, партии, offline-выдача, измерения, уведомления, LOST/FOUND, списание, карантин, исправление прошлых операций, перенумерация и удаление справочников. Не включать Kafka, Redis, микросервисы, Kubernetes или Event Sourcing framework.

## Требования и приёмка

| ID | Требование | Приёмка |
|---|---|---|
| REQ-01 | Строковые коды и отдельная идентичность сотрудника | Код `00001234` сохраняется буквально; замена карты не меняет employee_id; UC-01 |
| REQ-02 | Нормализованное хранение | Шкаф → полка → ячейка; номера уникальны в родителе; разные размеры структуры допустимы |
| REQ-03 | Только допустимое положение АКБ | STORED: cell задан, holder NULL; ISSUED: наоборот; неверная форма отвергается БД |
| REQ-04 | Четыре бизнес-команды | UC-02–05; нет произвольного PATCH состояния и удаления событий |
| REQ-05 | Получает и возвращает сам | TAKE задаёт holder=actor; RETURN от другого сотрудника даёт 409 NOT_CURRENT_HOLDER, ничего не меняет |
| REQ-06 | История неизменяема для приложения | Каждая принятая команда добавляет событие с версией, участниками, местами и временем; UPDATE/DELETE/TRUNCATE запрещены приложению |
| REQ-07 | Атомарность | Отказ до COMMIT не оставляет только состояние, только событие или только ключ |
| REQ-08 | Конкурентность | Два TAKE одной АКБ — один успех; две АКБ на одну ячейку — один успех |
| REQ-09 | Идемпотентность | Один ключ+запрос возвращает прежний результат; другой запрос с ним — 409 |
| REQ-10 | Быстрые чтения текущего положения | UC-06/08/09 читают batteries с индексами, без восстановления всей истории |
| REQ-11 | Сохранение ссылок | Замена карты и отключение пустой ячейки не ломают старые события |
| REQ-12 | API для демонстрации | OpenAPI содержит все маршруты, DTO, примеры, operationId, ошибки; Swagger Try it out после реализации |

Карта определяет участника команды, но не подтверждает его личность. 401/403 зарезервированы для будущего защищённого API и в макете не возвращаются. Для ограничения RETURN используется 409 как конфликт участника с текущим держателем.

## Выбранные упрощения

- Идентификаторы сущностей — UUID; условные inventory_code/credential — строки 1–128 символов, регистр и ведущие нули значимы, пробелы/управляющие символы запрещены. Это формат макета, не реальной маркировки.
- employee.name — 1–200 символов после trim. Табельного номера и модели АКБ на этом этапе нет; независимость employee_id от credential сохраняется.
- STORE создаёт АКБ уже в ячейке; отдельного NEW не требуется.
- У сотрудника может быть несколько credential. Отозванные значения повторно не назначаются для простоты демонстрации.
- После первого использования адреса мест не меняются; API перенумерации нет. Имена сотрудников в истории показываются текущие; юридически значимый снимок ФИО не обещается.
- `device_code` — необязательная строковая метка, заявленная клиентом; отдельный справочник устройств не нужен.
- Отключать можно только пустую ячейку; извлечение при отключённом родителе допускается, размещение запрещено. API отключения полок/шкафов/сотрудников вне этапа, поля сохраняют возможность расширения.
- Время recorded_at/updated_at назначает БД после получения блокировок; API выдаёт UTC RFC3339. Порядок одной АКБ — версия.
- Идемпотентные записи успешных команд сохраняются весь срок жизни демонстрационной БД. Неуспешные команды не резервируют ключ навсегда.

## Нефункциональные требования

- Одна PostgreSQL и одно Go-приложение; явные транзакции, pgx и SQL без ORM.
- Локальный запуск на loopback. Входной JSON ограничен 64 KiB; неизвестные, повторяющиеся поля и явный null в запросах отклоняются.
- Списки limit 1–100, по умолчанию 50; offset ≥ 0. Снимок между страницами не гарантируется.
- Предложенные технические пределы макета: ожидание блокировки 5 секунд, SQL-команды 10 секунд, HTTP-команды 15 секунд. Это настройки, а не заявленная измеренная производительность.
- Ошибки не содержат SQL, stack trace или данные подключения. Внутренний журнал может содержать request ID/код ошибки, без необходимости логировать полный credential.
- Проверки конкурентности и сбоев — в [verification.md](verification.md); SLA предприятия и гарантии восстановления в объём макета не входят.

## Состояние передачи

Существенные пользовательские правила определены. Остальные решения здесь — явные упрощения макета. Следующий этап: реализация согласованного целевого контракта, если пользователь её поручит. Существующий прототип отличается: разрешает чужой возврат, содержит loss и использует checkout/register; его тесты не подтверждают новое поведение.
