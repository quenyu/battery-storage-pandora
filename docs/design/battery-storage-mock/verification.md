# Проверка проектного пакета

29.09.2026. Относится только к [макету](spec.md). Проверка DDL/контракта не означает, что существующий Go backend уже реализует этот вариант.

## Фактически выполнено

- OpenAPI 3.0.3 проверен `openapi-spec-validator`: 19 путей, 25 HTTP-операций, 25 схем; 46 примеров проверены `openapi-schema-validator`.
- operationId уникальны. У всех изменяющих POST есть Idempotency-Key; POST /credentials/resolve является чтением и исключён из этого требования.
- DDL выполнен локальной PostgreSQL на тестовой БД внутри отдельной схемы и общей транзакции. Создание схемы, справочников и данных отменено ROLLBACK; отсутствие схемы после проверки подтверждено.
- Выполнена SQL-последовательность STORE → TAKE → RETURN своим держателем → MOVE; четыре события сохранились.
- Проверены 15 ожидаемых отказов: два положения одной АКБ; две АКБ в ячейке; повтор inventory_code; несуществующая ячейка; повтор номера полки; повтор credential; чужой credential автора; событие чужого возврата; MOVE в то же место; удаление исторической ячейки; пустой credential; UPDATE/DELETE/TRUNCATE истории; повтор ключа идемпотентности.
- Проверены сохранение событий после отзыва старого credential и отключения освобождённой ячейки, создание нескольких активных credential у сотрудника.

Инструменты этого прогона находятся в локальной рабочей папке `.local/build_mock_contract.py` и `.local/check_mock_design.py`; они не часть будущего backend. Валидаторы установлены локально в `.local/design-tools`. Публичные артефакты пакета — SQL, YAML и Markdown.

Не проверены исполнением: HTTP-обработчики нового контракта, конкурентные транзакции из двух соединений, потеря HTTP-ответа после COMMIT, проверка активности мест сервисом, Swagger Try it out нового контракта, права отдельной прикладной роли. Триггерный запрет изменения истории проверен; настройка роли — отдельная обязанность будущей реализации. Ни нагрузка, ни планы запросов не измерялись.

## Сценарии A–H для приёмки backend

| Сценарий | Действие | Ожидаемый результат и причина |
|---|---|---|
| A | АКБ в 1.1.1; Петров выполняет TAKE | 201; ISSUED, holder=Петров, ячейка свободна; событие содержит source=1.1.1. Все записи одной транзакцией |
| B | Петров снова выполняет TAKE | С новым ключом 409 BATTERY_ALREADY_ISSUED; со старым — первоначальный ответ без нового события |
| C | Сидоров одновременно выполняет TAKE той же АКБ | Один успех, второй 409 после ожидания FOR UPDATE. Не предписывается, кто выиграет; держатель ровно один |
| D | Петров возвращает в 1.2.4 | 201, STORED в свободной активной ячейке; RETURN сохраняет previous_holder=actor=Петров. Возврат Сидоровым — 409 NOT_CURRENT_HOLDER |
| E | Перемещение 1.2.4 → 2.1.2 | 201; expected_source соответствует БД; MOVE сохраняет оба места. Источник устарел — 409 SOURCE_MISMATCH |
| F | TAKE зафиксирован, ответ потерян; ТСД повторяет | Тот же ключ/запрос возвращает исходный статус/тело. Новый TAKE не создаётся, даже если позже уже был RETURN |
| G | Карту Петрова заменили | employee_id тот же; старый credential сохранён и отозван; новые команды по старому коду — 404; история читается, старые успешные команды повторяются |
| H | Освободившуюся ячейку отключили | 200, disabled_at задан; прежние события доступны; новое размещение — 409 LOCATION_DISABLED. Отключение занятой — 409 CELL_OCCUPIED |

## Что готово и следующий шаг

Проектный пакет готов для демонстрационного макета с явно записанными упрощениями. DDL и формат API проверены; проверки бизнес-транзакций по HTTP остаются будущему этапу реализации.

Первый шаг реализации: отдельная чистая схема/БД, роли владельца и приложения, STORE → GET состояния/истории с атомарным сохранением ключа. Затем TAKE с V-02–05/12, RETURN/MOVE и оставшиеся сценарии. Переход к Go-реализации не выполнялся в этом запросе.
